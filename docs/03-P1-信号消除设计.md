# P1 设计：多遍信号消除（Signal Subtraction）

> 前置：`docs/00-评估与总体设计.md`、`docs/02-测试报告.md`
> 目标：在不牺牲时延预算的前提下，显著提升解码召回率，向 JTDX 靠拢。
> 算法参考 JTDX（GPLv3）的 `subtractft8.f90` 思路，**代码全部自研**（见 §7 许可证）。

---

## 1. 背景与目标

P0 单遍解码在 `test/` 全量集上召回率 **72.6%**（942/1298）。人工核对漏解集中在：

1. **频率相邻的碰撞信号**（如 2378 Hz 与 2389 Hz 仅差 10 Hz，只解得强者）；
2. **弱信号 / 低信噪比**（参考 SNR ≤ −17 dB）。

JTDX 依靠「先解强信号 → 在时域重构并减去 → 再解弱信号」的多遍迭代显著提升召回。

**P1 目标**

| 指标 | 现状 | 目标 | P1 实测 |
| --- | --- | --- | --- |
| 召回率（test/ 全量） | 72.6% | ≥ 82%（力争 88%） | **80.7%**（默认）/ **81.9%**（调参） |
| 单时隙解码 P95 | ≈10–15 ms | ≤ 500 ms（力争 ≤ 300 ms） | **260–281 ms**（4 线程） |
| 多余解码（extra） | 2.0% | ≤ 4% | **2.9%**（默认）/ 3.3%（调参） |

## 2. 关键难点

- 候选的**频率分辨率仅 3.125 Hz**（`freq_osr=2`），**时间分辨率仅 80 ms**（`time_osr=2`）。相干相减要求频率误差 ≪ 1 Hz、时间误差 ≪ 1 ms。
- 本管线瀑布为**幅度量化（uint8）**，无相位，无法在瀑布域做复数相减。

## 3. 方案选型

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 频域复数相减（需相位瀑布） | 改用 `WATERFALL_USE_PHASE`，`monitor_resynth` 重构 | 上游实现不完整、2 符号窗粗糙，弃 |
| B. **时域重合成相减** | 由解码音调生成相位参考，在当前音频上估复包络并相减 | **采用**（对齐 JTDX 思路） |
| C. 幅度域“掩膜” | 直接改瀑布幅度 | 不严谨，弃 |

### 3.1 核心公式（自研实现，思路同 JTDX）

实测信号：`x(t) = a·cos(2πf t + φ(t) + θ)`
复相位参考：`ref(t) = exp(j(2πf' t + φ(t)))`（`φ` 为 GFSK 连续相位）

1. 混频到基带：`z(t) = x(t)·conj(ref(t))`
   `= (a/2)·exp(j(2π(f−f')t+θ)) + (a/2)·exp(−j(2π(f+f')t+2φ+θ))`
2. 低通（截止约 ±3 Hz）滤除倍频项，得复包络：
   `env(t) ≈ (a/2)·exp(j(2π(f−f')t+θ))`
3. 相减：`x(t) ← x(t) − 2·Re(env(t)·ref(t))`，精确抵消该信号。

**关键优点**：只要频率残差 `|f−f'|` 落在低通通带内（本例 ≤1.56 Hz < 3 Hz），残差会自然体现在 `env` 的相位斜率上，**无需显式频率精化**即可对齐。

### 3.2 时间精化（必需）

候选 `dt` 分辨率 80 ms，相干相减需 ≤1 ms。故：

- 以 `{x[n0+Δ+k]}` 与参考 `ref[k]` 的互相关模 `|Σ x·conj(ref)|` 为准则；
- 在 **前 12 个符号**、`Δ ∈ ±600` 采样内做粗搜（步长 8）→ 细搜（步长 1）；
- 取峰值 `Δ*` 作为消息起点（成本约 4 ms/条）。

## 4. 算法与实现

### 4.1 新增模块

```
native/api/ft8_gfsk.{h,c}      # 公共 GFSK 脉冲与复相位参考生成（供编码与相减复用）
native/api/ft8_subtract.{h,c}  # 时域重合成相减
```

`ft8_gfsk_reference()`：由 79 个音调生成 `exp(j·φ)` 的实/虚部（连续相位，参数与编码端一致）。

`ft8_subtract_signal(s, samples, n, tones, f0, dt)` 步骤：

1. 生成 `ref[0..L−1]`（`L = 79·n_spsym`）。
2. 时间精化得到 `Δ*`，令 `n0' = n0+Δ*`。
3. `z[k] = x[n0'+k]·conj(ref[k])`（越界置 0），补零到 FFT 长度 `N`（≥L 的 5-smooth）。
4. 低通：`H = FFT(h)/N`（`h` 为 `cos²` 窗、长度 `NF≈4000`、中心对齐、归一化和为 1）；
   `env = IFFT(FFT(z)·H)`。
5. 端点校正：用 `endcorr` 补偿信号边界处滤波器只覆盖部分抽头的衰减。
6. `x[n0'+k] −= 2·Re(env[k]·ref[k])`。

### 4.2 多遍驱动（`ft8api.c`）

```
resid = copy(samples)
seen  = {}                     // 按 payload+hash 去重
for pass in 0..passes-1:
    mon = monitor(resid);  cands = find_candidates(...)
    decoded = 并行解码(cands)
    new = decoded − seen; seen ∪= new
    if pass>0 and new is empty: break
    对 new 逐条 ft8_subtract_signal(resid, tones, f0, dt)   // 由强到弱
```

- `passes` 取 `cfg->decode_depth`（≤0 时启用消除默认 3）。
- 启用条件：`cfg->enable_subtract == true`；关闭时保持 P0 单遍路径。
- `ft8_message_result_t.pass` 记录命中遍次。

### 4.3 性能预算（12000 Hz，L=151680，N=153600，5-smooth）

| 步骤 | 成本 |
| --- | --- |
| 时间精化 | ~4 ms |
| 生成参考 + 混频 | ~1 ms |
| 2×FFT（`z`、`env`） | ~7 ms |
| 相减 | ~0.5 ms |
| **单条合计** | **~12 ms** |

- 典型每遍新增 5–10 条 → 每遍约 60–120 ms；3 遍约 0.2–0.4 s。
- 若超预算，优化：仅对 `snr ≥ 阈值` 的信号相减；或用抽取（先短 FIR 抗混叠再降采样）缩短 FFT。

## 5. 配置与 API

复用现有字段，无破坏性变更：

| 字段 | 含义 |
| --- | --- |
| `enable_subtract` | 开启多遍信号消除 |
| `decode_depth` | 遍数（≤0 时默认 3） |
| `min_sync_score` | 各遍沿用；后续可做分级阈值 |

CLI 已支持 `--subtract` / `--depth N`。

## 6. 验证与迭代

1. **单元验证**：`gen` 两条频率相邻消息（差 ~10 Hz）叠加成一个 WAV，验证单遍只解一条、开启消除后两条都解出。
2. **回归**：`ft8_cli bench test --subtract --depth 3`，对比召回率与耗时，记录到 `docs/02-测试报告.md`。
3. **消融**：分别测 1/2/3/5 遍，确定收益拐点。
4. **误码**：监控 extra 比例，必要时提高 `min_sync_score` 或加 CRC/位置校验。

## 7. 许可证与原创性

- 仅**参考** JTDX `subtractft8.f90` 的数学思路（复包络相减），不复制其 Fortran 代码；
- 本实现对相位参考生成、FFT 低通、端点校正、时间精化均为自研 C，沿用 MIT 基座；
- 保持整体 MIT，不引入 GPL 传染（与 `NOTICE` 一致）。

## 8. 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 频率残差超出低通通带 | 相减不干净 | 时间精化同时粗估频偏；必要时二次迭代 |
| 相邻信号相互污染 `env` | 相减引入残差 | 只在残差能量下降时接受；保留原始样本 |
| 误减真信号导致丢解 | 召回反降 | 相减前记录能量，相减后校验；保留单遍结果 |
| 耗时超预算 | 体验 | 仅相减强信号；抽取加速；遍数自适应 |
| 上游日志/断言 | 稳定性 | 保持 `-Wall` 干净，异常路径回退单遍 |

## 9. 实施顺序

1. 抽出 `ft8_gfsk`，编码端改用它（回归确保回环不变）。
2. 实现 `ft8_subtract`，用 §6.1 的合成用例验证。
3. 接入 `ft8api.c` 多遍驱动（`enable_subtract`）。
4. 全量回归，记录召回率/时延/extra，更新测试报告。
5. 按结果优化（阈值、遍数、抽取）。

## 10. P1 实测结果（2026-10-02）

### 10.1 实现落地

| 文件 | 说明 |
| --- | --- |
| `native/api/ft8_gfsk.{h,c}` | 抽出 GFSK 脉冲与复相位参考 `ft8_gfsk_reference()`，编码端与相减共用 |
| `native/api/ft8_subtract.{h,c}` | 时域重合成相减：粗对齐 → 频偏估计 → 细对齐 → FFT 低通复包络 → 端点校正相减 |
| `native/api/ft8api.c` | 新增 `decode_pass()`（单遍原始命中）、`decode_slot_multipass()`（多遍驱动）；`enable_subtract` 时走多遍，否则保持 P0 单遍路径 |
| `native/include/common/monitor.h` | 复用现有字段，无破坏性 API 变更 |

实际实现相对设计的增强：

1. **频偏估计**：逐符号相关相位做加权线性回归，得到 Δf 并调制参考，使 79 符号可相干；
   （设计原案未含此步，实测缺失时相减质量不足。）
2. **三段式对齐**：粗对齐（3 符号，容忍 ±1.56 Hz 频偏）→ 频偏校正 → 细对齐（16 符号，步长 1 样本）。
3. **端点校正**：`present(k)=Σ_{m=-NF/2}^{k} w(m)`，`corr=sumw/present`，覆盖信号首尾 NF/2 样本。

### 10.2 合成用例（碰撞验证）

- **用例 A**：两条消息相距 10 Hz、弱信号低 6 dB、同起点 → 单遍仅解强者，开启相减后**两条全解**。
- **用例 B**：相距 6.25 Hz、弱信号低 **30 dB**、起点相差 50 ms → 单遍解强者，开启相减后**两条全解**。
- 结论：在频率残差 ≪ 低通通带（±6 Hz）、时间经精化后，相减可有效“挖出”被压制的弱信号。

### 10.3 全量回归（Android x86_64 模拟器，4 线程，`test/` 60 文件 / 1298 条）

| 配置 | 命中 | 召回率 | extra | P50 | P95 |
| --- | --- | --- | --- | --- | --- |
| P0 单遍（基准） | 942 | 72.6% | 2.0% | 9.5 ms | 12.5 ms |
| **P1 默认**（`--subtract --depth 3`） | 1048 | **80.7%** | 2.9% | 203 ms | 260 ms |
| P1 调参（再加 `--time-osr 3 --candidates 280`） | 1063 | **81.9%** | 3.3% | 230 ms | 280 ms |

- **45 个文件召回提升，0 个下降**；追加第 4/5 遍与将 `min_sync_score` 降到 6 均无进一步收益（收益在 3 遍内收敛）。
- 原始输出：`test_results/p1_default_threads4.txt`、`test_results/p1_tuned_threads4.txt`。
- 单条相减成本约 12 ms（时间精化 + 2×FFT），典型每遍新增 6–10 条。
- 耗时 P95 ≈ 260–280 ms，满足「≤500 ms」；内存占用约 **6 MB**（scratch + 参考），另有每遍 monitor 重建。

### 10.4 剩余差距分析

漏解 235–250 条，分布集中于：

1. **极度拥挤频段**：如 `test_21.wav` 单文件含 30+ 条同时信号，强信号相减后仍有多条相互重叠，LDPC 难以分离；
2. **弱信号**（参考 SNR ≤ −16 dB）约 60 条，接近噪声下限；
3. 少量强信号漏解亦发生在拥挤文件中（相减残留 + 旁邻污染）。

进一步收敛需 P2 的 OSD/深度候选，以及更高频域分辨率（本管线 `freq_osr` 与 FFT 窗长耦合，无法单独提高）。

### 10.5 结论

- P1 目标基本达成：召回率 **+8.1 个百分点**，P95 在 500 ms 预算内，extra 未超 4%。
- 与「≥82%」目标差约 0.1–1.3 个百分点，差距集中在 30+ 信号/时隙的极端场景，属算法深度问题而非实现缺陷。
- 多遍消除开关通过 `ft8_decode_config_t.enable_subtract` + `decode_depth` 控制，默认关闭，不影响 P0 行为。
