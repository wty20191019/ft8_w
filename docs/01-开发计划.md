# FT8 Android 应用 —— C 层开发计划（P0）

> 对应设计：`docs/00-评估与总体设计.md`
> 目标：交付可编译、可测试、可 JNI 调用的 FT8 C 层编解码模块，单时隙解码 ≤1000ms（力争 ≤500ms）。

## 2. 任务分解与顺序

### 步骤 1：工程骨架（M0）
1. 建立 `native/` 目录结构（`include/`、`src/`、`jni/`、`tools/`）。
2. 从 `ft8_lib` 复用 MIT 源码：`constants/crc/ldpc/encode/decode/message/text/monitor/wave` + kissfft。
3. 编写 `native/CMakeLists.txt`：
   - `add_library(ft8 STATIC ...)`
   - 主机平台额外构建 `ft8_cli`（用于测试）。
4. 写 `NOTICE`，声明 `ft8_lib`（MIT, Kārlis Goba）来源。

### 步骤 2：编码模块（M1）
1. 封装 `ft8_encode_message`：`ftx_message_encode` → `ft8_encode` → `synth_gfsk`。
2. 支持 `lead_in_sec` / `tail_sec`（VOX 保护间隔）与 `amplitude`。
3. 提供 `ft8_encode_tones` 调试接口。
4. 自测：生成多种消息波形，再用解码链自解。

### 步骤 3：解码模块（M2）
1. 封装 `ft8_decode_slot`：`monitor_init/process` → `ftx_find_candidates` → `ftx_decode_candidate` → `ftx_message_decode`。
2. 实现呼号哈希表（`ft8_hash`）供解包使用。
3. 输出结构体 `ft8_message_result_t`（text/snr/dt/freq/score/ldpc_errors/pass/ap_type/crc）。
4. 去重：按 payload hash，避免同一信号多次上报。

### 步骤 4：公共 API 与会话（M3）
1. `include/ft8api.h`：配置结构 + 函数声明 + 版本。
2. 一次性接口 + 流式会话（`create/reset/feed/finalize/free`）。
3. CLI 工具 `ft8_cli`：
   - `ft8_cli decode <wav> [选项]`
   - `ft8_cli gen <message> <out.wav> [freq]`
   - `ft8_cli bench <dir>` → 命中率 + 时延 P50/P95

### 步骤 5：多线程（M4）
1. `ft8_thread` 抽象（pthread / Win32）。
2. 候选分块并行解码，主线程合并。
3. 基准调参：`num_threads`、`min_sync_score`、`ldpc_iterations`。

### 步骤 6：JNI 桥（M5）
1. `ft8_jni.cpp` 实现规划中的 Kotlin 签名。
2. 配置用 `float[]` 封送；结果用 `Array<String>`（字段 `|` 分隔）。
3. `JNI_OnLoad` 缓存类/方法，避免重复查找。
4. 写一份 Kotlin 调用示例（注释形式，随代码附上）。

### 步骤 7：测试与基准（M6）
1. 全量 `test/*.wav` 解码，解析对照 `*.txt`。
2. 统计 `matched / missed / extra`，计算命中率。
3. 记录主机 clang 与 Android（模拟器/真机）两组性能。
4. 结果写入 `docs/00-...md` 附录或单独的 `docs/02-测试报告.md`。

## 3. 验收清单

- [ ] 主机 clang 编译 `native/` 无错误无告警（`-Wall -Wextra`）。*（主机 LLVM clang 23.1.2 已安装；主机构建待补，当前以 NDK 构建为准）*
- [x] NDK 交叉编译 `arm64-v8a` + `x86_64` 静态库成功（各自含 `libft8.so`）。
- [x] 编码回环：`gen` 出的 WAV 能被 `decode` 解出同一文本。
- [x] 全量测试集命中率 ≈ `ft8_lib` 基线（72.6%，与上游同参数同源码）。
- [x] 单时隙解码 P95 ≤ 1000 ms（x86_64 模拟器实测 ≈11–15 ms，4 线程）。
- [x] P1 多遍信号消除：全量召回率 80.7%（默认）/ 81.9%（调参），Extra 2.9–3.3%，P95 ≈ 260–280 ms（详见 `docs/03` §10）。
- [x] P2.1 OSD 兜底译码：默认 `osd_depth=2`，召回 81.8%（+14），Extra 3.3%，P95 ≈ 234 ms；修复接受语义缺陷（详见 `docs/04` §4.7、`docs/02` §7.4）。
- [x] P2.2 逐符号频谱 SNR（WSJT-X 同源频谱噪声底口径）：解码文本不变（命中 1062、Recall 81.8%），对 WSJT-X 参考 R²=0.791、MAE≈3.5 dB（详见 `docs/04` §4.8、`docs/02` §7.5）。
- [x] JNI 桥编译进 `libft8.so`（armeabi 两 ABI 均通过）。
- [ ] Kotlin 侧 `System.loadLibrary("ft8")` 端到端往返联调（随示例 App，P3）。

> 验收详情见 `docs/02-测试报告.md`。
